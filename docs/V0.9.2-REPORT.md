# v0.9.2 report — one-command local n8n engine proof

## Why this checkpoint exists

v0.9.1 fixed the n8n 2.39.8 CLI import requirement for stable workflow IDs, but the last proof still depended on several manual steps: import the production webhook flow, activate it in the UI, run the local API in a second terminal, and call the webhook from a third terminal.

v0.9.2 removes most of that ceremony. It adds a dedicated inactive **manual-trigger engine-proof workflow** that can be imported and executed directly by the local n8n CLI. The proof uses a separate deterministic mock API on `127.0.0.1:3011`, so it does not depend on Ollama speed and does not interfere with the normal dashboard API on port 3001.

## Engine-proof sequence

```text
n8n Manual Trigger
  -> POST /research/analyze
  -> POST /campaign-kit
  -> GET /demo/status
  -> POST /proof/assert-local-safety
```

The final assertion endpoint returns non-2xx if the flow is unsafe or incomplete. The n8n execution therefore fails closed if any of these expectations are broken:

- a campaign ID exists
- `externalWrites=false`
- `livePublishing=false`
- approval is `WAITING` before a human acts
- delivery is `BLOCKED` before approval

A successful proof is persisted as `n8n.engine_proof` history and copied to `.runtime/n8n-engine-proof.json` for portfolio evidence.

## One-command Windows proof

Run:

```text
engine-proof-local-n8n-windows.cmd
```

The helper:

1. verifies the local `n8n` CLI and prints its version;
2. installs/checks the project-local TypeScript dependency;
3. builds and validates committed workflows;
4. starts an isolated deterministic API on port 3011;
5. imports `Ecom Engine Proof - CLI Local`;
6. executes it through the actual local n8n engine;
7. captures the persisted proof receipt;
8. shuts down the isolated API.

No workflow activation, Cloud account, platform credential, or external write is required.

## Additional hardening

- The n8n safety validator now allows only the normal local API port 3001 and the isolated proof port 3011.
- The local API exposes a fail-closed proof assertion endpoint and a read-only latest-proof endpoint.
- Windows diagnostics no longer fail the whole deterministic suite solely because a live Ollama generation times out. Set `STRICT_OLLAMA_SMOKE=true` when a strict live-model gate is required.
- Portfolio/recruiter handoff material is prepared so GitHub publishing does not require reconstructing the project story.

# v0.8.1 progress report

## Why this patch exists

The first live Windows/browser trial of v0.8.0 exposed a UX problem rather than a backend failure: approval and refresh actions had no busy/progress feedback, repeated clicks could overlap, and starting a new full demo silently created a new campaign whose approvals correctly reset to zero.

## Fixes

- Added `POST /approval/channel` for explicit per-channel bulk approval.
- Added an in-memory batch lock so repeated clicks cannot run the same campaign/channel approval concurrently.
- Made the bulk endpoint idempotent when a channel is already fully approved.
- Added visible per-channel approval counts.
- Added disabled/busy states for approval, delivery, and refresh buttons.
- Added explicit timeline refresh logging.
- Added RUN-page copy explaining campaign-specific approval resets.
- Added regression coverage for the dashboard UX and approval endpoint.

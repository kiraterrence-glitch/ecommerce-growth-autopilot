# v0.9.1 progress report — n8n 2.39.8 import compatibility

## Why this patch exists

The first real Windows CLI import on local n8n 2.39.8 failed with:

`SQLITE_CONSTRAINT: NOT NULL constraint failed: workflow_entity.id`

The committed workflow exports were valid for static contract tests but did not include a top-level workflow `id`. n8n 2.39.8's CLI import path requires an importable workflow identity before inserting into `workflow_entity`.

## Fix

- Added stable, unique top-level workflow IDs to all four committed local workflow exports.
- Added an n8n validator rule that rejects missing, malformed, or duplicate workflow IDs.
- Added a regression test covering import-compatible workflow identity metadata.
- Updated the Windows import helper to run n8n preflight validation before invoking the CLI and to print the detected local n8n version and workflow ID.
- Kept every workflow inactive, credential-free, local-only, and free of Code/Function business logic.

## Safety

This patch does not enable live publishing, external writes, or n8n Cloud. The portfolio workflow remains local-first and inactive by default.

## Remaining runtime gate

Run the patched workflow once inside the user's local n8n 2.39.8 engine, then run `local-n8n-proof-windows.cmd`. That engine-level proof is the only remaining n8n integration gate.

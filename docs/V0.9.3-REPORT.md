# v0.9.3 report — Windows n8n CLI runner hardening

## Why this patch exists

The first real Windows execution of the v0.9.2 one-command proof reached the installed n8n 2.39.8 CLI but failed before the workflow ran. The runner wrapped every argument in quotes, producing the equivalent of `n8n "--version"`. n8n 2.39.8 interpreted the quoted flag as a command token and returned `Command ""--version"" not found`.

## Fix

- Windows command serialization now leaves normal CLI tokens such as `--version`, `import:workflow`, and `--help` unquoted.
- Arguments are quoted only when required, such as a path containing spaces.
- The `/s` cmd.exe switch was removed from the runner to avoid quote-rewriting behavior.
- A regression test asserts the exact Windows command line used for the n8n version/import checks.
- The one-command proof runs in a fresh isolated local `N8N_USER_FOLDER` per run, so the user’s normal n8n browser/server profile is untouched.
- The one-command proof remains local-only, deterministic mock AI, no credentials, no external writes, and zero n8n Cloud executions.

## Runtime result

`finish-portfolio-proof-windows.cmd` completed successfully on Windows with local n8n Community Edition 2.39.8. The wrapper printed `PORTFOLIO PROOF COMPLETE`, created the runtime engine-proof receipt, and `release:preflight` passed. The verified safety state was zero n8n Cloud executions, `externalWrites=false`, and `livePublishing=false`.
